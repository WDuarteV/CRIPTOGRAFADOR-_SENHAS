1. Visão Geral das 4 Formas de Uso do Sistema

O sistema foi projetado em camadas modulares independentes para permitir tanto a validação rigorosa via terminal exigida pelo edital quanto a exploração visual e interativa de telemetria. Você pode utilizar o programa de 4 maneiras complementares:

Modo de Uso Comando Principal Quando Utilizar
1. Painel Web Visual (Zero-Interference) ./executar_interface.sh Para demonstrações visuais, visualização do Chunking por worker, criptografia/descriptografia interativa e inspeção dos 3 gráficos.
2. Binários Nativos C++ (CLI Direta) ./threads/app 4 10000000 84729 AvaliacaoSO2 Para avaliação direta na banca, medição pura no terminal e validação de equivalência com diff.
3. Assistente Interativo de Terminal python3 interface/cli_interativo.py Para execução guiada passo a passo via perguntas no próprio terminal Linux.
4. Scripts de Benchmark & Docker ./testes/benchmark_host.sh
./testes/benchmark_dock.sh		 Para rodar automaticamente as 5 baterias científicas no Host e com limitação de CPU (--cpus) e gerar os CSVs/PNGs.

2. Pré-Requisitos e Instalação de Dependências

Passo 1 Verificar ou instalar os pacotes essenciais do Linux e o Docker Engine

Abra o terminal na sua distribuição Linux e certifique-se de ter o compilador GNU C++ (g++), o utilitário make, o python3 e o docker instalados e ativos:

No Ubuntu / Debian / Linux Mint:

sudo apt update && sudo apt install -y build-essential g++ make python3 python3-matplotlib docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

No Arch Linux / Manjaro:

sudo pacman -S --needed base-devel gcc make python python-matplotlib docker
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

No Fedora / RHEL:

sudo dnf install -y gcc-c++ make python3 python3-matplotlib docker
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
Passo 2 Acessar a pasta raiz do projeto

Navegue pelo terminal até a pasta principal onde estão os módulos do projeto:

cd "/home/doublew/PROJETO SO2"

3. Passo a Passo: Compilação dos Motores C++

Cada um dos três paradigmas possui seu próprio diretório isolado (/sequencial, /processos e /threads) com um Makefile configurado com otimização máxima (-O3 -std=c++17 -Wall -Wextra e -pthread).

Passo Único Compilar os 3 módulos de forma limpa

Execute os comandos abaixo a partir da raiz do projeto para limpar binários antigos e recompilar os três executáveis nativos:

make -C sequencial clean all
make -C processos clean all
make -C threads clean all
  • ./sequencial/app — Motor monothread de referência (Baseline).
  • ./processos/app — Motor multiprocesso com fork(), mmap(MAP_SHARED) e waitpid().
  • ./threads/app — Motor multithread com std::thread, std::mutex e .join().

4. Passo a Passo: Execução Direta dos Binários C++ no Terminal

4.1. Sintaxe Unificada de Linha de Comando (CLI)

Todos os três executáveis obedecem rigorosamente à mesma assinatura dinâmica (sem valores fixos travados no código):

./<modulo>/app <workers> [tamanho] [chave] [senha]
Ordem Parâmetro Obrigatório? Valor Padrão Descrição
argv[1] <workers> Sim (em processos/threads) 1 (no sequencial) Quantidade de fluxos concorrentes (P ∈ {1, 2, 4, 8}).
argv[2] [tamanho] Opcional 10000000 Total de entradas N do dicionário (10 milhões = 320 MB).
argv[3] [chave] Opcional 84729 Semente numérica secreta para as 50 iterações modulares.
argv[4] [senha] Opcional "AvaliacaoSO2" Senha em texto claro a ser criptografada e descriptografada.
Exemplo 1 Executar a Versão Sequencial (Baseline Oficial)
./sequencial/app 1 10000000 84729 AvaliacaoSO2

O que acontece: Aloca 320 MB, calcula as 10.000.000 de posições em um único fluxo (~3,86 segundos), exibe o Checksum (5000000903112875), a senha criptografada e a senha descriptografada.

Exemplo 2 Executar a Versão Paralela com 4 Processos (POSIX IPC)
./processos/app 4 10000000 84729 AvaliacaoSO2

O que acontece: Mapeia 320 MB via mmap(MAP_SHARED), cria 4 processos filhos via fork() (cada um processando 2.500.000 posições), sincroniza o checksum com pthread_mutex_t (PTHREAD_PROCESS_SHARED), aguarda com waitpid() e conclui em ~1,81 segundos.

Exemplo 3 Executar a Versão Paralela com 4 ou 8 Threads (C++17)
./threads/app 4 10000000 84729 AvaliacaoSO2
./threads/app 8 10000000 84729 AvaliacaoSO2

O que acontece: Instancia 4 ou 8 threads via std::thread compartilhando o espaço de endereçamento, protege o checksum global com std::mutex, aguarda via .join() e reduz o tempo para ~1,77 s (4w) e ~1,12 s (8w — Speedup de 3,44x).

Exemplo 4 Validar a Equivalência Estrita de Saída com diff (Requisito da Banca)

Para comprovar que as versões Sequencial, Processos e Threads produzem exatamente o mesmo resultado bit a bit:

diff -u <(./sequencial/app 1 10000000 84729 AvaliacaoSO2 | sed -n "/\[RESULTADOS\]/,/\[TELEMETRIA\]/p") \
        <(./processos/app 4 10000000 84729 AvaliacaoSO2 | sed -n "/\[RESULTADOS\]/,/\[TELEMETRIA\]/p")

diff -u <(./sequencial/app 1 10000000 84729 AvaliacaoSO2 | sed -n "/\[RESULTADOS\]/,/\[TELEMETRIA\]/p") \
        <(./threads/app 4 10000000 84729 AvaliacaoSO2 | sed -n "/\[RESULTADOS\]/,/\[TELEMETRIA\]/p")

Resultado esperado: Nenhuma linha de diferença (código de retorno 0), confirmando identidade absoluta.

5. Passo a Passo: Uso do Painel Visual Web (Zero-Interference UI)

O projeto conta com uma interface web local construída para demonstrar visualmente o paralelismo sem interferir nos núcleos da CPU durante as medições.

Passo 1 Iniciar o Painel Visual

Na raiz do projeto, execute o script de inicialização:

./executar_interface.sh

(Alternativamente, você pode rodar diretamente python3 interface/server.py 5000 e abrir http://localhost:5000 no navegador).

Passo 2 Aba 1 — Execução Paralela, Chunking & Cifragem
  1. Escolha o Paradigma de Sistema Operacional (Sequencial, Threads ou Processos).
  2. Selecione a quantidade de Workers Concorrentes (P) (1, 2, 4 ou 8).
  3. Selecione o Limite de CPU (Cgroups / Docker): deixe em Host Físico para velocidade máxima ou escolha --cpus="1", "2" ou "4" para simular a restrição de hardware do container.
  4. Informe o Tamanho do Dicionário (N) (padrão oficial: 10.000.000), a Chave Modular (K) e a Senha.
  5. Clique em "🚀 Executar Motor C++ Paralelo & Medir Speedup".
  6. Observe no painel direito o Tempo de Geração, Tempo Total, Speedup (Sp), Eficiência (Ep), Checksum Global e, logo abaixo, o diagrama de Decomposição de Domínio (Chunking) mostrando o intervalo exato [start, end) de cada worker e a tabela indicando qual Worker gerou o token de cada letra da senha!
Passo 3 Aba 2 — Descriptografia Reversa no Dicionário
  1. Na Aba 1, após cifrar uma senha, clique no botão "➔ Inspecionar Reversão" (ou acesse diretamente a Aba 2 e clique em "📋 Carregar Última Senha Cifrada").
  2. Clique em "🔓 Executar Descriptografia Reversa & Mapear Partições".
  3. O sistema exibirá a Senha Original Reconstituída e uma tabela detalhando cada token recebido, o valor numérico após as 50 iterações, o código ASCII, o índice exato no dicionário e qual Worker paralelo (Wp) detém aquela fatia de memória.
Passo 4 Aba 3 — Os 3 Gráficos Obrigatórios & Benchmark (Host vs. Docker)
  1. Ao abrir a Aba 3, o sistema já carrega automaticamente os dados oficiais das 135 execuções (5 repetições por cenário com N=10.000.000).
  2. Analise os 3 Gráficos Obrigatórios exigidos pelo professor:
    • Gráfico 1: Tempo de Execução (s) por Workers (1, 2, 4, 8) comparando Sequencial, Processos e Threads.
    • Gráfico 2: Curva de Speedup Real (Sp) vs. Speedup Linear Ideal (y = x) demonstrando a Lei de Amdahl.
    • Gráfico 3: Host Físico vs. Container Docker / Cgroups (--cpus="1", "2", "4").
  3. Caso deseje rodar uma nova bateria ao vivo na hora, selecione o tamanho desejado e clique em "⚡ Executar Bateria ao Vivo no Kernel".
Passo 5 Aba 4 — Terminal CLI & Validação Automática diff

Clique no botão verde "✔ Validar Equivalência Estrita (diff Seq vs. Proc vs. Threads)" para executar os três binários simultaneamente e comprovar com diff zero que as saídas de ./sequencial/app, ./processos/app 4 e ./threads/app 4 são idênticas.

6. Passo a Passo: Uso do Modo CLI Interativo no Terminal

Se estiver em uma sessão puramente de terminal (SSH ou sem navegador) e quiser um menu interativo passo a passo:

Comando Iniciar o assistente interativo em Python
python3 interface/cli_interativo.py

O assistente fará 4 perguntas simples (com valores padrão caso pressione apenas Enter):

  1. Senha a ser criptografada (Padrão: AvaliacaoSO2).
  2. Paradigma de execução (1 = Sequencial, 2 = Threads, 3 = Processos).
  3. Quantidade de workers (1, 2, 4 ou 8 — Padrão: 4).
  4. Tamanho do dicionário (1 = 1.000.000, 2 = 10.000.000 — Padrão: 2).

Em seguida, ele executa o motor C++, mostra a tabela de telemetria e pergunta se deseja realizar a descriptografia reversa imediata.

7. Passo a Passo: Uso do Container Docker (/container/Dockerfile) e Limitação de CPU (--cpus)

O projeto possui o módulo completo de containerização em /container (contendo Dockerfile, run_docker.sh e README.md). Abaixo está o passo a passo completo tanto via comandos nativos do Docker quanto via script automatizado:

Passo 1 Iniciar o Serviço do Docker (Daemon) no Linux

Antes de construir ou rodar o container, certifique-se de que o serviço do Docker está iniciado e ativo:

# Inicia o serviço do Docker imediatamente e habilita no boot
sudo systemctl start docker
sudo systemctl status docker --no-pager
Passo 2 Construir a Imagem Docker do Projeto (docker build)

A partir da pasta raiz do projeto, execute o comando de build utilizando o arquivo container/Dockerfile (baseado em ubuntu:24.04, que copia os módulos e compila automaticamente sequencial, processos e threads com -O3):

docker build -t projeto-so2 -f container/Dockerfile .

# Verificar se a imagem 'projeto-so2' foi criada:
docker images | grep projeto-so2
Passo 3 Iniciar e Executar o Container com Limitação de CPU (docker run --cpus)

Execute diretamente os comandos exigidos na especificação do professor para testar o escalonador CFS do Kernel Linux sob restrição de 1, 2 e 4 núcleos:

# 1. Executar 4 Processos restritos a apenas 1 CPU (--cpus="1")
docker run --rm --cpus="1" projeto-so2 ./processos/app 4 10000000 84729 AvaliacaoSO2

# 2. Executar 8 Threads restritas a apenas 1 CPU (--cpus="1" - Alta Contenção)
docker run --rm --cpus="1" projeto-so2 ./threads/app 8 10000000 84729 AvaliacaoSO2

# 3. Executar 4 Threads restritas a 2 CPUs (--cpus="2")
docker run --rm --cpus="2" projeto-so2 ./threads/app 4 10000000 84729 AvaliacaoSO2

# 4. Executar 8 Threads restritas a 4 CPUs (--cpus="4")
docker run --rm --cpus="4" projeto-so2 ./threads/app 8 10000000 84729 AvaliacaoSO2
Passo 4 Alternativa Automatizada via Script Wrapper (./container/run_docker.sh)

Você também pode usar o script orquestrador ./container/run_docker.sh, que verifica se a imagem projeto-so2 já existe (fazendo o docker build automático caso necessário) e executa o docker run --rm --cpus="...":

./container/run_docker.sh 1 processos 4 10000000 84729 AvaliacaoSO2
./container/run_docker.sh 2 threads 4 10000000 84729 AvaliacaoSO2
./container/run_docker.sh 4 threads 8 10000000 84729 AvaliacaoSO2
Nota Técnica de Portabilidade: Se o daemon do Docker estiver ativo, o script executa docker build + docker run --rm --cpus="..." projeto-so2. Caso seja executado em uma máquina de laboratório onde o daemon do Docker não esteja instalado, o script aciona automaticamente o subsistema nativo cgroups v2 do Kernel Linux via systemd-run --user --scope -p CPUQuota=... e taskset, aplicando exatamente a mesma restrição física de quota no escalonador CFS!
Passo 5 Reexecutar as Baterias de 5 Execuções e Regerar os 3 Gráficos PNG

Para rodar novamente toda a coleta experimental (Host + Docker) e atualizar os arquivos em /testes/resultados/:

# 1. Coleta de 5 execuções por cenário no Host Físico (gera tempos_host.csv)
./testes/benchmark_host.sh 10000000 84729 AvaliacaoSO2

# 2. Coleta de 5 execuções por cenário sob --cpus 1, 2 e 4 (gera tempos_docker.csv)
./testes/benchmark_dock.sh 10000000 84729 AvaliacaoSO2

# 3. Cálculo de média, desvio padrão, speedup e geração dos 3 gráficos .png
python3 testes/plot_graficos.py
